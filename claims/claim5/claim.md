# Claim 3 - Precision (Part Three)

These testcases evaluate the claims about TrustLeech's active VMI capabilities made in Section 5.3 of the paper. 

To reproduce these tests, execute the `run.sh` file accompanying this claim. 
This opens a new QEMU VM, using the images generated by the install script. 
Log into the VM using the username `root`.

To verify the claims, execute the following steps:


## Preamble:

### Network Connection 
This test case (and the following ones) will require two QEMU VMs to interact with each other via a simulated network connection, which we implemented using QEMU user networking. 


## Testcase 1. 

### Inject Malware 
First, inject one of the Malware kernel modules:
```
modprobe spy 
modprobe sutekh 
modprobe diamorphine
```


### Start TrustLeech 
Next, inject TrustLeech in the QEMU environment:
```
modprobe trustleech
```

Next, we again have to connect a second VM hosting the VMI appliance:
For this, execute the `run_2.sh` script in another terminal which will open another QEMU instance.
Here, also login with `root`, then execute: 
```
cd /usr/bin 
./vmi_client_4
```

### Trigger Events 
Now, execute one of the userspace apps that make use of the malware modules:
```
cd /usr/bin 
./user_spy 
./user_sutekh
./user_diamorphine
```
