# Claim 1 - Performance 

These testcases evaluate the performance claims made in Section 5.1 of the paper.
To reduce the runtime of the experiments, we only execute each testcase once.

To reproduce these tests, execute the `run.sh` file accompanying this claim. 
This opens a new QEMU VM, using the images generated by the install script. 
Log into the VM using the username `root`.

To verify the claims, execute the following steps:


## Preamble:
To generate the ground truth of the CoreMark-Pro benchmark, we first execute it on the Hypervisor:
```
chmod +x /usr/bin/coremark-pro.sh
/usr/bin/coremark-pro.sh
```
Save the results to some file for later comparision.

Next, start a VM inside the QEMU environment to then execute the benchmark in:
```
lkvm run -k /boot/Image -d /rootfs.ext4 --console virtio --nested # this may take a little
# Login with Root, then
chmod +x /usr/bin/coremark-pro.sh
/usr/bin/coremark-pro.sh
```
Finally, poweroff the VM by executing 
```
poweroff
```

### Network Connection 
This test case (and the following ones) will require two QEMU VMs to interact with each other via a simulated network connection, which we implemented using QEMU user networking. 
To enable the connection between the VMs, you need to execute the following line:
```
sudo ifconfig <INTERFACE>:0 192.168.1.6 up
```
Where `<INTERFACE>` must be replaced with the currently active network interface used, e.g., `eth0`.
This can be found out by using `ifconfig`.

## Testcase 1. Injection Slowdown
First, this test case evaluates the performance costs of injecting the TrustLeech-hypervisor. 
The time is measured by a kernel module used to initialize the injection.
This module can be installed using:

```
modprobe trustleech
```
This should print the duration (in Nanoseconds) it took to inject the TrustLeech-hypervisor. 

### Connect with a second VM 
The TrustLeech-hypervisor initially starts in introspection mode, meaning that it halts the system to await VMI commands.
Therefore, we must connect to it and send an according `CONTINUE` command.

For this, execute the `run_2.sh` script in another terminal which will open another QEMU instance.
Here, also login with `root`, then execute: 
```
cd /usr/bin 
./vmi_client
```
This should resume excution of the first QEMU instance. 


## Testcase 2. Runtime Slowdown
To evaluate the slowdown, we execute `CoreMark-Pro` in the now virtualized Hypervisor:
```
chmod +x /usr/bin/coremark-pro.sh
/usr/bin/coremark-pro.sh
```
We then again spawn a (now nested) VM and repeat the benchmark:

```
lkvm run -k /boot/Image -d /rootfs.ext4 --console virtio --nested # this may take a little
# Login with Root, then
chmod +x /usr/bin/coremark-pro.sh
/usr/bin/coremark-pro.sh
```
Finally, poweroff the VM again by executing 
```
poweroff
```

## Testcase 3. Removal Slowdown 
First, this test case evaluates the performance costs of removing the active TrustLeech Hypervisor. 
The time is measured by the kernel module used to initialize the removal.

For this, execute 
```
rmmod trustleech
```
which finally prints the time it took to remove the TrustLeech-hypervisor.
